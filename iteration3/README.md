# GridLock FDIA Detector (CNN+LSTM, Niu et al. 2019-style)

## Run it
```
pip install pandapower torch scikit-learn pandas numpy
python run_all.py
```
Runs preprocess -> train (both variants) -> evaluate, end to end, on CPU in a couple minutes.
This will create `data/dataset.npz` and `checkpoints/*.pt` locally (not included here — they're
regenerated by the pipeline, and the .npz alone is ~18MB).

## What's here
- `preprocess.py` — builds the DC state-estimation Jacobian H for IEEE 14-bus
  (pandapower `case14`), simulates normal AR(1) grid trajectories, and injects
  stealthy FDIAs (a = H @ c, so the classic bad-data residual test doesn't
  flag it). Also generates a `proposed action` feature per timestep from an
  independent (unattacked) local generator telemetry channel.
- `model.py` — CNN encoder (spatial, per-timestep) + LSTM (temporal, over the
  window) + MLP head. `use_action` flag toggles the action-fusion branch.
- `train.py` — trains `with_action` and `without_action` checkpoints with
  class-weighted cross-entropy (attacks are the minority class).
- `evaluate.py` — precision/recall/F1/confusion matrix on a held-out test
  split, plus a with-vs-without comparison table.
- `run_all.py` — orchestrates the above.

## The twist
The paper detects FDIAs from raw measurements alone. Here, the LLM agent's
proposed action (derived from independent local telemetry, not the SCADA
feed the attacker corrupts) is fed in as a second channel. On the held-out
test set this took F1 from ~0.29 (measurements only) to ~0.70 (with action),
because a subtle, low-magnitude stealthy attack often isn't enough to move
the raw measurements outside the noise floor — but it does create a
disagreement between "what the sensors report" and "what's actually true,"
which is exactly the (grid state, proposed command) feature vector
GridLock's ML layer needs. Numbers will vary a bit by RNG seed.
